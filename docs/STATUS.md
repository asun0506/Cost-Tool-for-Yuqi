## 本次验证

通过 `npm test` 重跑以下检查，全部针对 `dist/cost-bom-tool.html` 的实际脚本：

- 交付结构、脚本语法、CSP 哈希一致性、外部资源引用检查。
- EBOM 主导结构；S 公共用量和 O 不计入合计但保留单价。
- 自动/缓存映射、价格冲突选择、重复上传沿用确认价、导入不覆盖工程结构。
- 原文件逐字节下载还原、历史快照不变、手动价格变更日志、加密备份恢复与审计链。
- 分配置单车 Δ、单价 Δ × 用量、正负差额、BOM 同步换算、重复保存去重。
- 二级分类汇总、未分类、历史分类快照和空状态。

这些是 Node VM 中使用合成数据的逻辑检查，部分 DOM 和保存操作使用替身，不包含真实浏览器端到端验收。

## 待验收与限制

1. 使用实际 EBOM / Cost BOM 的脱敏 Excel 文件核对列识别、合并表头、数值格式、重复零件号与大表性能；现有检查主要使用合成 CSV。
2. 在目标公司浏览器实测文件打开、创建项目、IndexedDB 限制、XLSX 解析、截图和备份恢复。
3. 完成最新 EBOM/Cost BOM 工作流的页面交互验收；此前进度中该流程仍处于兼容性收尾阶段。
4. 本地审计哈希链用于发现意外变化，不是第三方见证或服务器不可篡改审计。
5. 当前源码集中在单个 HTML 中；后续可拆分源码并引入构建，但应继续交付单文件。

## 后续建议顺序

先完成真实模板和目标浏览器验收，再处理发现的问题；随后补浏览器自动化覆盖，最后考虑源码模块化。早期计划中列出的 SheetJS、esbuild 等不代表当前依赖；当前实现没有外部运行依赖。
