## 逐项对照

| 板块 | 已实现 | 尚未实现或实现范围有限 |
| --- | --- | --- |
| 成本周报 | last stage / current stage 日期选择、成本瀑布图、期间变更统计、分配置成本、未关闭风险、周报快照及打印 | 历史阶段的风险状态、等级和进度未按审计完整回溯；生成的周报只保存未解决高风险的明细，未覆盖全部等级的风险 |
| Cost BOM管理 | 上传、相对前版比较、价格冲突选择、修改成本价格与价格状态、分类/责任人维护、版本和原文件存档 | 不是上传表格全部字段的自由编辑器；工程结构、用量和配置由 EBOM 提供，不能在 Cost BOM 页面直接修改全部来源字段 |
| EBOM 基线管理 | 上传、最新版完整明细、相对前版比较、工程配置/用量变化、版本与原文件追溯 | 未提供界面内修改零件名称、用量、配置等工程数据并保存新基线的功能；需修改源表后重新导入 |
| 成本变更管理 | 手动新增、编辑、多零件/多配置价差、会议及截图、每次保存保留前后值 | 缺少整条成本变更的删除/作废入口及对应保存逻辑。编辑时“移除零件”只删除该变更中的一个零件，不等于删除整条变更 |
| 成本风险管理 | 新增、编辑、删除/恢复、等级/状态直接切换、周进度新增和删改、业务操作审计 | 参考图中的日常管理要求基本覆盖；历史阶段回溯的缺口见成本周报 |
| 锁板记录 | EBOM/Cost BOM 导入时版本锁板和原文件存档；按配置保存只读成本快照、导出 XLSX | 未提供同一时间点一次冻结 EBOM、Cost BOM、全部成本变更、全部风险及成本周报，并下载完整锁板包的流程 |

## 关键缺口的实际边界

1. **一键全量锁板尚未实现。** 当前手动成本快照主要保存当前配置的价格明细、汇总和 EBOM 版本信息，未把变更、风险和周报同时冻结。工作区 JSON 备份虽然能导出完整状态，但它是独立操作，不是锁板编号下的一份关联快照。
2. **EBOM 页面不支持直接编辑业务数据。** 表格工具仅修改展示格式、筛选和宽度，不会修改工程数据。
3. **成本变更缺少整条删除/作废。** 如后续补齐，必须同时处理已进入/未进入 BOM 的变更对汇总、瀑布图和历史周报的影响。
4. **Cost BOM 的“编辑”是有限字段维护。** 如果参考图希望全部上传字段都能在页面内编辑，当前尚未达到；如果仅指成本价格、状态、分类等字段，则已有相应功能。
5. **历史日期下的风险信息不完全可还原。** 成本与变更有历史还原逻辑，但风险的创建、修改、状态切换与进度修改尚未在历史阶段还原中完整处理。因此指定过去的 current stage 时，风险区域可能仍体现后来的状态。
6. **周报快照与“所有核心信息”仍有范围差距。** 快照存有分配置成本和期间变更，但风险明细只包含未解决高风险；也不是整个 EBOM、Cost BOM 的完整数据副本。

## 核对依据

源码：dist/cost-bom-tool.html。

- Cost BOM / EBOM：renderBOMDetails、renderLatestEbom、renderImports、renderCostImports、openCreateDialog 中的 priceForm、attributesForm 保存分支。
- 成本变更：renderChanges、saveChangeForm、buildChangeRecord。渲染仅提供“更新变更”，保存分支只有新增和更新。
- 风险：updateRiskField、buildRiskProgressUpdate、riskProgressEntries、setRiskDeleted。
- 锁板与周报：lockSnapshot、weeklyReport、exportLock、renderWeeklyReportHistory、renderReportPreview。
- 历史还原：currentStageProject、historicalProject。
- 审计：commitMutation、makeEventPayload、renderAudit、verifyAuditChain；表格显示工具独立保存展示偏好。

## 建议优先顺序

先补一键全量锁板与成本变更作废，再明确 EBOM/Cost BOM 的可编辑字段；历史周报验收前补齐风险的按时点还原。以上为后续建议，本次没有自动实现这些额外业务功能。
